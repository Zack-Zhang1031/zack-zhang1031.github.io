风控模型把老板的亲戚拒贷了，老板问「为什么」——你答「模型输出的概率是 0.83」是过不了关的。欧盟 GDPR 给 automated decision 配了「解释权」，国内《个人信息保护法》第 24 条同样要求「透明、公平、公正」。**可解释性不是学术情怀，是合规刚需 + 调试利器 + 信任桥梁**。

这篇主攻 SHAP——当前特征归因事实上的标准，顺带讲清它和其他方法（LIME、反事实、注意力）的边界。

**前置阅读**：建议先读 [集成学习：随机森林与 XGBoost](/posts/ensemble-learning-rf-xgboost/)、[机器学习基础](/posts/ml-basics-scikit-learn/)。

## 先分清：两种「解释」

- **全局解释**：模型整体上怎么看问题——哪些特征重要、方向和形状如何（收入越高越好还是倒 U 型？）。用于建模者自查、向管理层汇报。
- **局部解释**：对**这一个样本**为什么这样判——这位客户被拒，贡献最大的三个因素是什么。用于客服答复、个案申诉、合规审计。

很多混乱源于混用：特征重要性强 ≠ 能解释单个决策（重要性全局平均可能掩盖局部分化）。SHAP 的优雅之处在于：**局部解释天然加总成全局解释**，一套理论两头通吃。

## SHAP：博弈论给 ML 的礼物

### 原理三分钟版

SHAP 的思想来自合作博弈的 Shapley 值：把预测看成「所有特征合作完成的游戏」，每个特征的贡献 = 它加入各种特征组合时带来的边际收益的平均。

$$\phi_i = \sum_{S \subseteq F \setminus \{i\}} \frac{|S|!(|F|-|S|-1)!}{|F|!} [f(S \cup \{i\}) - f(S)]$$

用人话：**把特征 i 分别放进所有可能的特征子集里，看它的加入让预测变了多少，加权平均**。这个公式保证了三个漂亮性质：

1. **有效性（Efficiency）**：所有特征的 SHAP 值加起来 = 预测值 − 基准值。解释是「完备」的，无遗漏。
2. **对称性**：贡献相同的两个特征 SHAP 值相同。
3. **一致性**：模型改进使某特征贡献变大，其 SHAP 值不会反而变小。

代价是计算量——「所有子集」是 2^|F| 个。所以有了各种近似实现：TreeSHAP（树模型精确快速）、KernelSHAP（模型无关但慢）、DeepSHAP（深度模型近似）。

### TreeSHAP 实战（XGBoost，生产最常见）

```python
import shap
import xgboost as xgb

model = xgb.XGBClassifier().fit(X_train, y_train)
explainer = shap.TreeExplainer(model)
shap_values = explainer.shap_values(X_test)

# 1. 全局：特征重要性蜂群图（一张图看方向+分布+影响）
shap.summary_plot(shap_values, X_test)

# 2. 全局：单特征的依赖图（看形状——线性？倒 U？阈值效应？）
shap.dependence_plot("age", shap_values, X_test)

# 3. 局部：单个样本的瀑布图（为什么这个人被拒）
shap.plots.waterfall(shap.Explanation(
    values=shap_values[i], base_values=explainer.expected_value,
    data=X_test.iloc[i], feature_names=X_test.columns))
```

读蜂群图的口诀：横轴是 SHAP 值（对预测的贡献），颜色是特征值大小（红高蓝低）——「年龄红色点在右侧」= 年龄越大越倾向预测正类。依赖图看形状：平台期、拐点、非单调，都是和业务对话的弹药。

### 局部解释的业务话术

瀑布图给出的故事是这样的：「基准违约率 5% → 近 6 个月查询次数 8 次（+12%）→ 信用卡使用率 92%（+8%）→ 收入稳定（−3%）→ 最终 22%，超过 15% 阈值，拒绝」。客服可以直接念，申诉可以逐项核对——**局部解释让模型决策变得可以对账**。

## 深度模型与 LLM 的解释

- **DeepSHAP/GradientSHAP**：DeepLIFT 与 SHAP 的结合，传播归因到输入层。图像模型的显著图（saliency map）本质同源。
- **注意力不是解释**：注意力权重高 ≠ 因果贡献大（Jain & Wallace 2019 的著名论文：换掉注意力权重预测可以不变）。可以看，别当证据。
- **LLM 场景**：可解释性转向「推理过程可审计」（CoT 外露）、「来源可追溯」（RAG 引用）——归因对象从特征变成了文档片段。我 [RAG 项目](/posts/rag-project-retrospective/)里强制答案附引用编号，就是 LLM 时代的解释方案。

## SHAP 的坑（我全踩过）

1. **特征相关性的幽灵**。收入和负债率强相关时，SHAP 会把贡献在相关特征间「分摊」，单个看都「不太重要」，业务方以为都不重要。解法：相关特征先聚类合并，或用 `shap_values` 的分组解释。
2. **TreeSHAP 的「特征不存在时」假设**。计算 f(S) 需要「抹掉」某些特征——TreeSHAP 默认用训练分布的边缘化，特征相关时会评估到不真实的样本组合（收入百万 + 年龄 5 岁）。这是所有归因方法的理论软肋，心知肚明即可。
3. **把 SHAP 当因果**。SHAP 说的是「模型用了什么」，不是「现实中什么导致什么」。「提高信用卡使用率导致被拒」是模型行为；「降低使用率就能通过」是行动建议——中间隔着因果推断的鸿沟，话术上别越界。
4. **计算成本**。KernelSHAP 在大样本上慢到不可用——树模型用 TreeSHAP（精确且快），深度模型上 DeepSHAP，别头铁用模型无关方法硬算。

## 其他方法速览：什么时候不用 SHAP

| 方法 | 一句话 | 何时用 |
|------|--------|--------|
| 特征重要性（内置） | 树的分裂增益统计 | 快速全局概览，但偏向高基数特征 |
| Permutation importance | 打乱某列看指标掉多少 | 任意模型，验证集上的可信全局 |
| LIME | 局部扰动 + 线性近似 | 文本/图像的局部解释，但采样不稳定 |
| 反事实解释 | 「改什么能翻转决策」 | 给用户可执行的建议（ actionable recourse） |
| 部分依赖图 PDP | 边际效应曲线 | 单特征形状，比 SHAP 依赖图更「因果化」的错觉 |

反事实值得多说一句：它回答的是用户真正的问题——「我该怎么办」。「如果你的信用卡使用率降到 60% 以下，申请就能通过」。生成方式：在特征空间搜索离原样本最近且预测翻转的点。注意要给**可行**的建议（「年龄减 3 岁」不是建议），所以实用系统会约束搜索空间在可行动特征上。

## 可解释性的工作流整合

我的经验是三个固定动作：

1. **建模时**：训练完必跑 summary_plot + 依赖图——经常能发现数据泄漏（某个特征 SHAP 一枝独秀到可疑，查下去果然是标签泄漏）。
2. **上线前**：抽 20 个边界样本（接近阈值的）人工过一遍瀑布图，确认模型的「理由」符合业务常识。
3. **线上**：监控 SHAP 值的分布漂移——特征贡献结构的突变比预测分布漂移更早暴露问题（和 [MLOps 那篇](/posts/ml-experiment-tracking-monitoring/)的监控体系衔接）。

## 踩坑排查

| 现象 | 原因 | 解法 |
|------|------|------|
| summary_plot 全挤在中部 | 模型欠拟合，特征都没学到 | 先提模型性能再谈解释 |
| 某特征 SHAP 异常高 | 疑似标签泄漏/特征穿越 | 查特征生成时间线，八成是泄漏 |
| 同一样本两次解释不同 | KernelSHAP/LIME 采样随机性 | 设 random_state；树模型换 TreeSHAP |
| 相关特征重要性被稀释 | 贡献分摊 | 特征分组解释或合并相关特征 |
| 业务方质疑「解释不合理」 | 模型学到了伪相关 | 用解释反哺建模：剔除伪特征重训 |
| 深度模型 SHAP 跑不动 | 用了 KernelSHAP | 换 DeepSHAP/Integrated Gradients |

## 练习

1. 在 Titanic 数据集上训练 XGBoost，生成 summary_plot 和 age 的依赖图，用三句话向「业务方」解释模型逻辑。
2. 找一个被模型拒绝的样本，生成瀑布图，写出三段式的拒绝原因说明（可直接发给用户的那种）。
3. 人为制造特征泄漏（把标签加噪后当特征），看 SHAP 如何暴露它——训练你的「泄漏嗅觉」。
4. 对同一模型分别计算内置 feature_importance、permutation importance、SHAP 全局重要性，对比三个排序的差异并解释原因。

## 面试常问

**Q：SHAP 和特征重要性有什么区别？**
内置重要性（gain/cover）统计训练时该特征用于分裂的收益，偏向可被频繁切分的高基数连续特征，且只反映训练集。SHAP 基于 Shapley 值，有公理化保证（有效性/对称性/一致性），能给每个样本每个特征带方向的贡献值，可加总成预测。简单说：重要性是「模型多爱用这个特征」，SHAP 是「这个特征对每个决策贡献多少」。

**Q：为什么说注意力权重不是解释？**
Jain & Wallace 的实验：① 可以找到与原始注意力分布差异巨大但预测不变的对抗注意力；② 随机置换注意力权重，预测经常不变。注意力是模型的内部计算状态，和输入对输出的因果贡献没有必然绑定。可作调试参考，不可作决策证据。

**Q：SHAP 能用于因果推断吗？**
不能。SHAP 解释的是模型的行为（关联层面），不是世界的因果结构。要回答「干预 X 会怎样」需要因果推断框架（do-calculus、工具变量、双重差分）。混淆两者会给出危险的行动建议——模型认为「戴呼吸机 ↔ 死亡风险低」不代表「该给病人戴呼吸机」（经典的相关性陷阱）。

**Q：反事实解释和 SHAP 的分工？**
SHAP 回答「为什么是现在这个结果」（归因过去），反事实回答「怎样能改变结果」（指导未来）。面向用户申诉和可行动建议时反事实更直接；面向模型调试和合规报告时 SHAP 更系统。成熟系统两者都提供。

**Q：线性模型已经可解释了，为什么还要这些方法？**
① 现实问题的非线性（交互、阈值效应）线性模型表达不了，牺牲精度换解释经常不划算；② 「可解释」不只是系数——高维线性模型的几百个系数人也看不懂，仍需要重要性排序和归因；③ 后验解释（post-hoc）让「用最强模型 + 配解释工具」成为可能，不再被迫二选一。
