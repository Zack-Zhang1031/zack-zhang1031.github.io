## 系统调参：网格、随机与分层搜索

以领域分类的逻辑回归管道为例，把调参从"手动试几个值"升级成"定义搜索空间"：

```python
from sklearn.model_selection import GridSearchCV

param_grid = {
    "tfidf__max_features": [10000, 20000, 40000],
    "tfidf__ngram_range": [(1, 1), (1, 2)],
    "tfidf__min_df": [3, 5, 10],
    "clf__C": [0.1, 1, 10, 100],
}

search = GridSearchCV(pipe, param_grid, cv=5,
                      scoring="f1_macro", n_jobs=-1, verbose=1)
search.fit(train["text_all"], train["field"])
```

网格 × 5 折 × 上面这个空间 = 360 次训练，文本数据上可能要跑几小时。两个提速手段：

**随机搜索（RandomizedSearchCV）**：超参超过 4 维时，随机采 60 组通常能找到网格搜索 90% 的最优区域，成本只有 1/6。

**分层搜索**：先粗后细。第一轮对数刻度扫 C ∈ [0.01, 100] 找数量级，第二轮在最优值附近线性细分。特征参数（ngram、min_df）先单独定，再调模型参数——特征和模型参数联动搜索的组合爆炸不值得。

调参结果全部进实验记录（[研究方法](/posts/research-methods-ai/)的纪律），包括**没赢的参数组合**——它们证明了搜索的充分性。

## 学习曲线：诊断该加数据还是该换模型

分数上不去时，先别急着换模型，画学习曲线诊断问题性质：

```python
from sklearn.model_selection import learning_curve

sizes, train_scores, val_scores = learning_curve(
    search.best_estimator_, train["text_all"], train["field"],
    train_sizes=np.linspace(0.1, 1.0, 8), cv=5, scoring="f1_macro")
```

两条线的形态直接给出行动指令：

- **训练分 ≈ 验证分，都低**（高偏差）：模型太简单或特征不够。动作：加特征、加 ngram、换更强模型。加数据没用。
- **训练分 ≫ 验证分**（高方差）：过拟合。动作：加正则、减特征，或者——**加数据确实有用**，验证分随数据量的斜率还往上走，收集更多数据是正确投资。
- **两条线收敛到同一水平且平缓**：当前模型+特征的天花板到了，继续投入的边际收益递减，该去改进数据质量或重新定义任务。

学习曲线是"下一步往哪使劲"的决策工具。没有它，调参就是玄学。

## 最终评估：封存测试集只摸一次

系列三所有模型迭代都在训练集交叉验证上进行，现在到了验收时刻：拿出从[第 2 课](/posts/research-ml-02-field-classification/)就封存、整个调参过程从未碰过的测试集，跑一次最终评估：

```python
final_model = search.best_estimator_
pred = final_model.predict(test["text_all"])

report = classification_report(test["field"], pred, output_dict=True)
# 同时输出置信度区间的自助法估计
from sklearn.utils import resample
f1s = []
for _ in range(1000):
    idx = resample(range(len(test)))
    f1s.append(f1_score(test["field"].iloc[idx], pred[idx],
                        average="macro"))
print(f"宏 F1: {report['macro avg']['f1-score']:.3f}, "
      f"95% CI: [{np.percentile(f1s, 2.5):.3f}, {np.percentile(f1s, 3+94.5):.3f}]")
```

带置信区间的报告是[研究方法](/posts/research-methods-ai/)一课"结果要可检验"的落地：0.812 ± 0.006 比干巴巴的 0.812 多回答了"这个数稳不稳"。

## 模型选择报告：M2 的核心交付物

把系列三所有候选模型放进同一张对比表，写正式的模型选择报告：

| 模型 | 宏 F1 (CV) | 训练耗时 | 推理延迟 | 可解释性 | 结论 |
|---|---|---|---|---|---|
| TF-IDF + 逻辑回归 | 0.812 ± 0.006 | 3 min | <1ms/篇 | 系数可读 | **入选** |
| TF-IDF + LinearSVC | 0.818 ± 0.005 | 2 min | <1ms/篇 | 无概率 | 备选 |
| 元数据 + HGB | 0.61 | 15 min | 2ms/篇 | 特征重要性 | 文本信息不可替代 |

选择逻辑要写清楚：LinearSVC 分数略高但无概率输出，平台需要置信度做"低置信降级人工"（[第 2 课](/posts/research-ml-02-field-classification/)定的需求），所以逻辑回归入选。**模型选择的第一标准是需求匹配，不是分数最高**——这份报告就是这句话的证据。

## 踩坑排查

| 症状 | 原因 | 处理 |
|---|---|---|
| 网格搜索跑了通宵 | 空间太大 × 全量数据 | 先子集粗扫，再全量精调 |
| 调参后测试分反降 | 测试集被反复使用导致过拟合 | 封存测试集只在验收时用 |
| 最优参数贴着搜索边界 | 边界设窄了 | 沿该方向扩展范围重搜 |
| CV 分数与最终测试分差很多 | 切分分布漂移 | StratifiedKFold；检查时间泄漏 |
| 换台机器结果变了 | 随机性未固定 | random_state 全链路固定 |
| joblib 加载后预测不一致 | 保存时环境版本不同 | 保存时记录 sklearn 版本 |

## 面试常问

**Q：学习曲线怎么用？**
训练/验证分数随数据量的两条曲线：同低→高偏差（加特征换模型）；差距大→高方差（加正则或加数据，看验证线斜率是否还在升）。它回答"下一步该投数据还是投模型复杂度"。

**Q：为什么模型选择不能只看分数？**
分数之外还有需求约束（要不要概率输出）、成本约束（训练/推理耗时）、运维约束（可解释性、体积）。需求匹配优先——略低分数但满足置信度需求的模型，优于高分黑箱。

**Q：怎么防止调参过拟合测试集？**
训练/验证/测试三分：调参只看交叉验证，测试集封存到最后验收用一次；验收不满意需要迭代时，重新切分或收集新数据，不要在同一测试集上反复。

**Q：随机搜索为什么常常不输网格搜索？**
超参对结果的影响高度不均——有效的维度往往只有一两个。随机搜索在相同预算下对每一维的探索更密，命中有效维度的概率反而高于稀疏网格（Bergstra & Bengio 的经典结论）。
