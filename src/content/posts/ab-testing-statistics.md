「新模型点击率提升了 0.3%，上线吗？」——这个问题我在评审会上听过无数次，而回答质量天差地别。有人会说「提升了就上」，有人会说「样本量多少？p 值多少？实验跑了几天？周几开始的？」。**前者在做决定，后者在做决策**。A/B 测试是数据科学里「科学」含量最高的部分，也是面试里最能区分人的部分。

这篇把 A/B 测试拆成工程流水线：实验设计 → 样本量预估 → 运行与监控 → 统计推断 → 决策与复盘，每一步给 Python 代码和真实坑点。

## 假设检验：一个反直觉的框架

A/B 测试的统计内核是假设检验，它的逻辑是反着的：**先假设「没效果」（原假设 H₀），再看数据有多不可能**。

- H₀（原假设）：新策略没有效果，观察到的差异只是随机波动。
- H₁（备择假设）：新策略真有效。
- p 值：**如果 H₀ 为真**，出现当前或更极端数据的概率。p = 0.03 意味着「纯属运气造成这么大差异的概率只有 3%」——够小（< 显著性水平 α，常取 0.05），我们拒绝 H₀，认为效果显著。

最常见的误读必须钉死：**p = 0.03 不是「新策略有效的概率是 97%」**，也不是「效应有 3% 概率是巧合」这种贝叶斯解读。频率学派的 p 值只陈述「在 H₀ 下数据的极端程度」。这个误读在业务方那里极其普遍，解释清楚是数据科学家的日常。

两类错误是对称的风险：

| | H₀ 真（没效果） | H₀ 假（真有效） |
|---|---|---|
| 拒绝 H₀（上线） | **一类错误 α（假阳性）**：白上线 | 正确 |
| 不拒绝（不上线） | 正确 | **二类错误 β（假阴性）**：错过优化 |

α 控制「误报率」（通常 0.05），1−β 是「统计功效」（power，通常要求 0.8）。功效不足的实验等于没做——差异真实存在你也检测不出来。

## 样本量：实验前必须算，不是跑完再说

「跑多少样本够」取决于四个量：基线转化率、最小可检测效应（MDE）、α、power。二分类指标（点击率/转化率）的公式：

$$n = \frac{(z_{1-\alpha/2}\sqrt{2\bar{p}(1-\bar{p})} + z_{1-\beta}\sqrt{p_1(1-p_1)+p_2(1-p_2)})^2}{(p_2-p_1)^2}$$

不用背，statsmodels 一行：

```python
from statsmodels.stats.power import TTestIndPower, NormalIndPower
from statsmodels.stats.proportion import proportion_effectsize

# 基线转化率 5%，想检测 +0.5pp（相对提升 10%）的变化
effect = proportion_effectsize(0.05, 0.055)
n = NormalIndPower().solve_power(
    effect_size=effect, alpha=0.05, power=0.8, ratio=1)
print(f"每组需要 {int(n):,} 样本")   # 每组约 60,000+
```

几个违反直觉但重要的直觉：

- **基线越低、MDE 越小，样本量爆炸式增长**。检测 5%→5.1% 需要几十万样本每组；检测 5%→6% 只要几千。所以「小效应大流量」才配做实验，小流量产品别硬测微小优化。
- 样本量**必须在实验前算好**，然后跑满再分析。「边跑边看，显著了就停」是最经典的作弊（见下文多重比较）。

## 实战：完整分析一次实验数据

假设实验跑了 14 天，对照组 52,000 用户 2,600 次转化，实验组 51,800 用户 2,720 次转化：

```python
import numpy as np
from statsmodels.stats.proportion import proportions_ztest, confint_proportions_2indep

n_a, c_a = 52000, 2600   # 对照组
n_b, c_b = 51800, 2720   # 实验组

# 两比例 z 检验（单侧：我们只关心 B 是否更好）
z, p = proportions_ztest([c_b, c_a], [n_b, n_a], alternative='larger')

# 效应量与置信区间
diff, ci_low, ci_high = confint_proportions_2indep(
    c_b, n_b, c_a, n_a, compare='diff', method='newcomb')

print(f"转化率: A={c_a/n_a:.4%}  B={c_b/n_b:.4%}")
print(f"绝对提升: {diff:+.4%}  95%CI [{ci_low:+.4%}, {ci_high:+.4%}]")
print(f"z={z:.2f}, p={p:.4f}")
```

输出解读的三个层次：

1. **p < 0.05**：统计显著——差异大概率不是运气。
2. **置信区间不含 0**：和 p 值等价的信息，但 CI 还告诉你效应的范围。
3. **业务显著性**：CI 下界是 +0.03pp——「真实提升可能只有万分之三」。即使统计显著，值不值得上线看业务成本。**统计显著 ≠ 业务显著**，这是新手最容易掉的坑。

连续指标（人均时长、客单价）用 t 检验或非参数检验：

```python
from scipy import stats

# 方差齐性未知，用 Welch's t（别默认 equal_var=True）
t, p = stats.ttest_ind(durations_b, durations_a, equal_var=False)

# 分布严重偏态（收入类指标常态），上 Mann-Whitney U
u, p_mw = stats.mannwhitneyu(durations_b, durations_a, alternative='greater')
```

## 六大翻车现场：实验设计的坑

这些是我见过/犯过的真实事故，比统计公式值钱：

**1. 边跑边看（peeking problem）**。每天看一眼 p 值，哪天显著了哪天停——假阳性率会从 5% 膨胀到 30%+。数学本质：多次重复检验。正确姿势：事先定好样本量，跑满一次性分析；或者上序贯检验（mSPRT、always-valid p-value）。

**2. 多重比较**。一次实验看 20 个指标，总有一个「显著」——20 个指标各 5% 假阳性，至少一个假阳性的概率 = 1−0.95²⁰ ≈ 64%。对策：事先声明主指标（只有一个！），次要指标用 Bonferroni 或 FDR 校正，或者干脆只当探索性参考。

**3. 辛普森悖论**。总体看 B 组差，分组看 B 组每个细分都好——因为分组样本结构不同。真实案例：新算法总体 CTR 降了，但拆开看新客老客都升了——因为新算法吸引了更多低 CTR 的新客进来，结构变了。对策：分析时既看总体也看分层，警惕比例变化。

**4. 分流不均（SRM）**。Sample Ratio Mismatch：设计 50/50，实际 48.7/51.3，卡方检验显著——说明分流机制有 bug（比如某端上报丢失），此时**所有指标结论作废**。SRM 检查是每个实验的第一步，成本一行代码：

```python
from scipy.stats import chisquare
stat, p = chisquare([n_a, n_b])   # p < 0.01 → 分流有问题，停止分析
```

**5. 新奇效应与周周期**。用户对新界面有短期好奇，第一周数据虚高；周末和工作日行为不同。对策：实验至少跑满整数个自然周（7/14 天），别在周中开始周中结束；对新奇效应敏感的功能看「老用户子群」的数据。

**6. 网络效应与干扰**。用户互相影响时（社交、拼车、市场类），随机分流到个人会破坏独立性——对照组的行为被实验组「污染」。对策：按社群/城市/时间片分流（cluster randomization、switchback），这是因果推断的前沿，至少要知道它的存在。

## 实验平台的最小功能清单

自己搭或评估公司内部平台时，按这个清单核对：

- 分流：稳定的哈希分流（同一用户永远同组）、支持分层互斥实验层
- SRM 自动检查，异常自动熔断
- 指标守护：主指标 + 护栏指标（收入、崩溃率、延迟），护栏恶化自动降级
- 样本量计算器内置，实验前强制预估
- 方差缩减：CUPED（用实验前数据做协变量校正，等效样本量 +30~50%）

CUPED 值得一提，它是大厂的标配但教程里很少讲：用实验前的行为 X 校正实验指标 Y（Y_cv = Y − θ·X，θ 取相关系数），方差降多少取决于 X 和 Y 的相关性。用户实验前活跃度和实验期行为相关性通常 0.5+，方差降 25%，等效于样本量 ×1.33——**白送的实验灵敏度**。

## 上线决策框架

数据都显著了，上还是不上？我的决策矩阵：

| 情形 | 决策 |
|------|------|
| 主指标显著正向，护栏无恶化 | 全量 |
| 主指标正向但 CI 下界 < 业务最小价值 | 看工程成本，低成本上，高成本弃 |
| 主指标不显著但方向正、功效不足 | 延长时间/增大样本，别急着宣判 |
| 主指标显著负向 | 回滚，复盘假设 |
| 主指标不动、护栏恶化 | 回滚 |

最后一步永远别省：**全量后监控长期效应**。实验期两周的显著提升，可能在全量三个月后衰减（用户习惯后新奇感消失）。留 5% 流量做长期 holdout 组，是大厂验证长期价值的做法。

## 踩坑排查

| 现象 | 原因 | 解法 |
|------|------|------|
| p 值天天波动，忽显著忽不显著 | 边跑边看 | 定死样本量，跑满再分析 |
| 实验组对照组量级对不上 | 分流 bug / 上报丢失 | SRM 卡方检查，查分流日志 |
| 指标显著但全量后没效果 | 新奇效应 / 实验期太短 | 跑整数周，看老用户子群，长期 holdout |
| 小效应怎么测都不显著 | 样本量不够（功效不足） | 事先算 n，或加大 MDE 预期 / CUPED 降方差 |
| 同一实验不同人算出不同结论 | 口径不一致（去重逻辑、时间窗） | 指标定义文档化，分析代码版本化 |
| 转化率类指标波动巨大 | 样本里混了机器人/异常流量 | 先做反作弊过滤再进分析 |

## 练习

1. 模拟实验：基线转化率 8%，真实提升 0.8pp。用 numpy 生成两组二项分布数据，跑 z 检验；重复 1000 次模拟，统计「在 H₀ 为真时拒绝 H₀」的频率——应当接近 5%，亲手验证 α 的含义。
2. 写 peeking 模拟：实验期间每天算一次 p 值，只要某天 <0.05 就停。重复 1000 次，看假阳性率膨胀到多少。
3. 用 statsmodels 算样本量：基线 3%，MDE 相对提升 5%/10%/20%，画出「MDE-所需样本量」曲线。
4. 实现 CUPED：造一份「实验前活跃度 X 与实验期时长 Y 相关 ρ=0.6」的模拟数据，对比校正前后置信区间宽度。

## 面试常问

**Q：p 值的准确定义？常见误读？**
在 H₀ 为真的前提下，观察到当前或更极端结果的概率。三大误读：① p = H₀ 为真的概率（错，频率学派不给假设赋概率）；② 1−p = 结论可复现的概率（错）；③ p > 0.05 证明没效应（错，可能是功效不足）。

**Q：一类错误和二类错误的关系？**
此消彼长：α 定得更严（0.05→0.01），假阳性降但假阴性升（功效降）。固定 α 下提升功效的三条路：增大样本、增大真实效应（做更大的改动）、降低方差（CUPED/分层）。样本量计算本质就是在这四个量之间解方程。

**Q：为什么要跑满整数周？**
用户行为有强周周期（周末/工作日差异），跑 5 天或 10 天会让两组经历的「星期结构」不对等，引入系统偏差。整数周保证两组都完整经历所有星期类型。

**Q：什么时候用 t 检验、z 检验、卡方、非参数？**
比例类二项指标（转化/点击）大样本 → 两比例 z 检验；连续均值 → Welch's t 检验；分类分布差异 → 卡方检验；偏态/小样本/秩相关 → Mann-Whitney U 等非参数。默认记住 Welch 不用 Student（不等方差假设更安全）。

**Q：如何提高实验灵敏度（同样流量测更小的效应）？**
① CUPED 方差缩减；② 分层抽样保证组间协变量平衡；③ 触发分析（只分析真正接触到功能的用户，但要警惕选择偏差）；④ 更聚合的实验单元（cluster 分流减少干扰）；⑤ 延长周期。组合拳能把 MDE 压到原来的 1/2~1/3。

**Q：AA 测试是什么，为什么做？**
两组都上对照版本，跑完整分析流程。期望：指标无显著差异、SRM 通过。AA 测出问题（假阳性率显著偏离 5%）说明平台分流/埋点/统计链路有 bug——它是实验平台的「体检」。
