「找出异常」和「分类」看起来像，但有个致命区别：**你手里没有异常样本**。设备故障、网络入侵、信用卡盗刷——异常要么稀有到攒不够训练集，要么模式天天变（今天的欺诈手法明天就过时）。异常检测的回答是：**不学「异常长什么样」，只学「正常长什么样」，偏离正常的就是异常**。

这篇讲三条主流路线（孤立森林 / One-Class SVM / AutoEncoder）、时序场景的特殊处理，以及最头疼的「没标签怎么评估」。

**前置阅读**：建议先读 [模型评估指标与类别不平衡](/posts/model-evaluation-metrics-imbalance/)、[K-Means 聚类](/posts/ml-kmeans-clustering/)、[时间序列分析](/posts/time-series-analysis/)。

## 先划边界：什么时候用异常检测而不是分类

| 情形 | 选择 |
|------|------|
| 有足够异常标签（几百+）且模式稳定 | 监督分类（不平衡处理即可） |
| 异常极少、模式多变、新异常不断出现 | 异常检测 |
| 完全无标签，只要「最可疑的 top-N」 | 异常检测（排序用法） |

现实项目常是混合：异常检测做初筛排序 → 人工审核积累标签 → 标签够了转监督。[评估与不平衡那篇](/posts/model-evaluation-metrics-imbalance/)讲的是后者，这篇讲前者。

## 孤立森林：最快最好用的首选

### 原理：异常点更容易被「孤立」

随机选特征、随机选切分点，递归切分直到每个样本被孤立——**异常点孤僻，几刀就被切出来；正常点抱团，要切很多刀**。所以「平均孤立所需路径长度」就是异常分：路径越短越异常。

```python
from sklearn.ensemble import IsolationForest

iso = IsolationForest(
    n_estimators=200,
    contamination=0.02,      # 预估异常比例，决定阈值
    random_state=42)
iso.fit(X_train)             # 注意：训练集应基本为正常样本

scores = -iso.score_samples(X_test)   # 越大越异常
preds = iso.predict(X_test)           # -1 异常 / 1 正常
```

三个参数要点：`contamination` 决定切分线位置（设为预估异常率，拿不准就 0.01~0.05 扫）；树的数量 200 足够；**它不需要异常标签，但训练集要尽量「干净」**——混入大量异常会污染「正常」的定义。

优势：快（线性复杂度）、高维友好、几乎不用调参。是工业界异常检测的第一基线。

## One-Class SVM：学一个包住正常的边界

思想：在高维空间找一个超平面/超球，把绝大多数正常样本包在内部，外面的就是异常（支持向量数据描述 SVDD 的近亲）。

```python
from sklearn.svm import OneClassSVM

ocsvm = OneClassSVM(kernel="rbf", nu=0.02, gamma="scale")
ocsvm.fit(X_train)
preds = ocsvm.predict(X_test)
```

`nu` 是异常比例上界（类似 contamination）。现实评价：**原理优雅但工程上被孤立森林全面压制**——核方法在大数据上慢（O(n²)~O(n³)）、对特征缩放敏感（必须先 StandardScaler）、高维下 RBF 核的距离度量退化。小数据（<1 万）、低维场景可以用，否则跳过去孤立森林。

## AutoEncoder：用重构误差检测异常

深度学习路线：训练一个「压缩-重建」网络，**只喂正常样本**——网络学会重建正常的模式。来一个异常样本，重构误差必然大（它没学过）。

```python
import torch
import torch.nn as nn

class AE(nn.Module):
    def __init__(self, dim, hidden=32):
        super().__init__()
        self.enc = nn.Sequential(nn.Linear(dim, 64), nn.ReLU(), nn.Linear(64, hidden))
        self.dec = nn.Sequential(nn.Linear(hidden, 64), nn.ReLU(), nn.Linear(64, dim))
    def forward(self, x):
        return self.dec(self.enc(x))

model = AE(dim=X_train.shape[1])
# 只用正常样本训练，loss = MSE(重建, 原样本)
# 推理：anomaly_score = ((model(x) - x) ** 2).mean(dim=1)
```

阈值从哪来？没有标签时的标准做法：**用训练集（正常样本）重构误差的分布定阈值**——比如取 99 分位数，超过即异常。AutoEncoder 在非线性结构复杂的数据上（图像、序列）超过孤立森林，但换来的是训练成本、超参敏感（瓶颈维度 hidden 是关键：太大恒等映射，太小正常也重建不好）。

变体：VAE 用重构概率、GANomaly 用判别器特征差——思想同根，工程复杂度递增。

## 时间序列异常：另一个物种

表格异常检测假设样本独立，时序数据违反这个假设。时序异常分三种，处理思路不同：

- **点异常**：单个点离谱（温度传感器突跳到 500°C）——滚动窗口统计：偏离 rolling mean ± 3σ 即报。
- **上下文异常**：数值本身正常但出现时机不对（凌晨三点的大额交易）——必须带时间特征（hour/dow）再检测。
- **集合异常**：一段序列的模式异常（波形形状变了）——需要序列级方法：LSTM 预测误差、STL 分解后看残差。

```python
# 最简单的时序点异常：滚动 Z-score（先跑通再谈复杂模型）
import pandas as pd

roll = series.rolling(window=48, center=True)
z = (series - roll.mean()) / roll.std()
anomalies = series[abs(z) > 3]
```

业务监控场景（QPS、错误率）我首推 [时间序列篇](/posts/time-series-analysis/)的 STL 分解 + 残差阈值，可解释、好调、够准。别一上来 LSTM。

## 无标签怎么评估：诚实面对灰色地带

这是异常检测最难的部分，几种现实策略：

1. **借标签评估**：攒一小批人工标注的异常（哪怕 50 个），算 Precision@K——「模型排的 top 100 里有多少真异常」。这是业务最关心的口径：审核团队每天能看 100 个，命中率是多少。
2. **合成异常**：往正常数据里注入扰动造伪异常（特征打乱、极端值），测检出率。注意合成异常≠真实异常，只能相对比较不同方法。
3. **稳定性检验**：不同时间窗的异常率是否稳定——某天异常率突然 10 倍，先查数据管道再查模型。
4. **人工抽检**：随机抽模型判「最正常」的样本让人看——如果里面混着明显异常，模型在漏报。

**诚实结论：异常检测的效果评估永远是半定量的**。把它定位成「人工审核的放大器」而不是「自动判决机」，期望就不会错位。

## 组合打法：我的风控实战配方

```
孤立森林（快筛，全量打分）
   + 规则引擎（黑名单、确定性规则，抓「已知异常」）
   + 业务特征上的统计告警（时序滚动 Z-score）
   → 三路分数加权排序 → top 500/天 → 人工审核
   → 审核结果回流 → 攒标签 → 6 个月后评估转监督分类
```

要点：**异常检测上线第一天就要设计好「标签回流」**——每条人工审核结论都存下来，它是你从「无监督」走向「半监督」的唯一桥梁。

## 踩坑排查

| 现象 | 原因 | 解法 |
|------|------|------|
| 孤立森林报的「异常」全是某类正常用户 | 训练集本身含多类正常模式 | 先分群再分别检测；或检查特征是否该保留 |
| contamination 设 1% 实际报出 15% | 训练集被异常污染 | 清洗训练集，或先用大阈值粗筛再重训 |
| One-Class SVM 全员异常 | 特征没缩放，距离失真 | StandardScaler 是 OCSVM 的前置条件 |
| AutoEncoder 异常分不出层 | 瓶颈维太大，恒等映射 | 减小 hidden，监控训练集重构误差是否足够小 |
| 白天告警少凌晨告警爆 | 没用上下文特征 | 加 hour/dow，或分时段建模 |
| 上线后异常率逐月漂移 | 正常模式本身在演化 | 定期用新数据重训（滚动窗口） |

## 面试常问

**Q：孤立森林为什么对高维友好？**
它不做距离计算，只做单特征随机切分——避开了高维空间距离集中度（curse of dimensionality 让所有点对距离趋同）的坑。每棵树只看一维，特征多了只是候选池变大。这也是它快的原因：建树深度 log(n)，预测是查路径长度。

**Q：AutoEncoder 检测异常的前提假设？**
「异常样本在训练分布之外，所以重建不好」。失效场景：① 异常和正常长得太像（重构误差分离不开）；② 模型容量过大，连没见过的异常也能重建（恒等映射风险）；③ 训练集本身混入了异常（把异常也学了）。所以瓶颈维度和训练集洁净度是两个命门。

**Q：异常检测怎么设阈值？**
没有标签时的三种现实锚点：① 业务容量锚点——每天能处理 N 条，就取 top N 对应的分数；② 统计锚点——训练集分数的 99/99.5 分位；③ 比例先验——contamination 按领域经验（欺诈通常 0.1%~2%）。上线后按人工反馈滚动校准，阈值是活的。

**Q：和监督分类的本质差异是什么？**
监督学的是「两类边界」，需要两类都有代表性样本；异常检测学的是「单类的范围」，只需要正常样本。前者上限高（有标签指导），后者覆盖广（能发现没见过的新异常类型）。对抗性场景（欺诈手法演化）异常检测更鲁棒；模式稳定场景监督分类更准。成熟系统两者串联。

**Q：怎么处理「正常」本身在缓慢变化？**
概念漂移问题。策略：滚动时间窗重训（只用近 3 个月数据）、在线/增量更新（River 库）、给旧样本降权。监控侧：跟踪异常率的长期趋势，漂移和真异常的区分靠「渐进 vs 突变」——渐进是正常演化该重训，突变是真事件该告警。
