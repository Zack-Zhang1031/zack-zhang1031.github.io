语音识别（ASR，Automatic Speech Recognition）的任务一句话说清：**把声波变成文字**。智能音箱听懂你的话、会议纪要自动生成、视频自动加字幕，背后都是它。

我做语音相关项目之前有个误解，以为这是个"调用 API 就行"的成熟领域。实际做下来发现：API 确实能调，但**效果不好时你根本不知道往哪改**——是采样率不对、是音频太吵、是领域词不认识，还是语言模型没选对。这篇先把"声波怎么变成文字"的链路讲清楚，再上手实战。

## 声波是怎么变成数字的

麦克风采集到的是连续声波，计算机只能处理离散数字，中间隔着一个**采样**过程：

- **采样率**：每秒采多少个点。电话音质 8kHz，标准语音 16kHz，CD 音质 44.1kHz。ASR 模型基本都吃 16kHz——喂错采样率是新手第一个坑。
- **位深度**：每个点用多少 bit 表示振幅，常见 16bit。
- **声道**：单声道（mono）还是双声道（stereo）。ASR 只需要单声道。

一段 10 秒的 16kHz 单声道音频，在计算机里就是 16 万个浮点数。直接拿这串原始波形喂模型效率太低，所以有了特征提取。

## MFCC：把波形压成"语音的指纹"

人耳对频率的感知不是线性的——我们对低频变化敏感，对高频变化迟钝。MFCC（梅尔频率倒谱系数）就是按人耳特性设计的特征：

1. **分帧**：把音频切成 25ms 的小段，帧间重叠 10ms（语音在这么短的窗口内近似平稳）。
2. **傅里叶变换**：每帧从时域转到频域，看这一帧有哪些频率成分。
3. **梅尔滤波**：按人耳感知特性把频率轴压缩（低频细、高频粗）。
4. **取对数 + 离散余弦变换**：得到每帧十几维的 MFCC 系数。

一段 10 秒音频经过 MFCC，变成大约 1000 帧 × 13 维的矩阵——比 16 万个原始采样点小两个数量级，却保留了语音识别需要的关键信息。librosa 一行就能算出来：

```python
import librosa

# 加载音频并强制转成 16kHz 单声道
y, sr = librosa.load("speech.wav", sr=16000, mono=True)

mfcc = librosa.feature.mfcc(y=y, sr=sr, n_mfcc=13)
print(mfcc.shape)   # (13, 帧数)
```

## 模型演进：从拼接系统到端到端

了解演进路线有助于理解现在为什么这么简单：

**传统时代**：声学模型（GMM-HMM，后来是 DNN-HMM）把 MFCC 映射到音素，发音词典把音素拼成词，语言模型把词连成通顺的句子。三个模块分开训练、分开调， pipeline 复杂，每个环节都要专家知识。

**端到端时代**：一个神经网络直接从频谱特征输出文字。CTC 解决了"音频帧和文字对不齐"的问题；RNN-Transducer 支持流式识别；Transformer/Conformer 结构把准确率推到新高度。代表就是 OpenAI 的 Whisper——68 万小时多语言数据训练，中文直接可用，开源免费。

对应用开发者来说，现在的结论很简单：**先上 Whisper，效果不够再考虑微调或领域方案**。

## Whisper 实战：中文语音转文字

```python
# pip install openai-whisper
import whisper

model = whisper.load_model("small")   # tiny/base/small/medium/large

result = model.transcribe(
    "meeting.mp3",
    language="zh",           # 显式指定中文，避免自动检测出错
    initial_prompt="以下是普通话会议录音，涉及人工智能、模型训练等术语。",  # 领域提示
)

print(result["text"])
for seg in result["segments"]:
    print(f"[{seg['start']:.1f}s - {seg['end']:.1f}s] {seg['text']}")
```

几个实战要点：

**模型尺寸怎么选。** tiny/base 速度快但中文错误率高；small 是速度和质量的甜点，会议纪要场景够用；large 质量最好但显存要吃 10GB 且慢。CPU 上用 small，有 GPU 上 medium 起步。

**initial_prompt 是低成本提分器。** 它相当于给模型的"上下文预告"。会议里全是专业术语时，把关键词写进 prompt，识别准确率肉眼可见地提升。还能用它控制输出繁体/简体和标点风格。

**segments 带时间戳。** 做字幕、定位"某人说了什么"全靠它。每个 segment 有起止秒数，可以直接生成 SRT 字幕文件。

## 工程化：长音频和脏音频

真实场景的音频不是教科书里的干净 10 秒录音：

**长音频切分。** 一小时的会议录音直接喂模型会内存爆炸。标准做法是先做 VAD（语音活动检测，把静音段剔掉），再按静音点切成 30 秒内的块逐块识别：

```python
# 用 silero-vad 或 webrtcvad 做语音活动检测后切分
# 伪代码示意流程：
# chunks = vad_split("meeting.mp3", max_duration=30)
# texts = [model.transcribe(c)["text"] for c in chunks]
```

**降噪与归一化。** 背景噪声大时，先做降噪（noisereduce 库）再识别；音量过小的录音先做响度归一化。音频质量对识别率的影响比换模型更大——垃圾进垃圾出。

**格式转换。** 各种来源的音频格式五花八门，用 ffmpeg 统一成 16kHz 单声道 wav 是最稳的预处理：

```bash
ffmpeg -i input.m4a -ar 16000 -ac 1 -c:a pcm_s16le output.wav
```

## 评估：WER 怎么算

语音识别效果的通用指标是 **WER（词错误率）**：

$$WER = \frac{S + D + I}{N}$$

S 是替换错误数，D 是删除数，I 是插入数，N 是参考文本总词数。WER 越低越好，中文场景常以字为单位计算（CER）。Python 里用 `jiwer` 库：

```python
from jiwer import wer

reference = "今天会议讨论模型训练进度"
hypothesis = "今天会议讨论模型训练进展"
print(wer(reference, hypothesis))
```

评估自己系统时，准备 50-100 条人工转写的音频作为测试集，每次改预处理或换模型都跑一遍 WER——没有这个数字，所有"优化"都是玄学。

## 踩坑排查清单

| 症状 | 原因 | 处理 |
|---|---|---|
| 识别结果全是乱码/英文 | 中文音频被当成其他语言 | 显式 `language="zh"` |
| 结果没有标点 | 模型/prompt 问题 | initial_prompt 里加一句带标点的示例 |
| 专业术语全错 | 领域词没见过 | initial_prompt 塞入术语；量大考虑微调 |
| 长音频 OOM 或极慢 | 没切分 | VAD + 按静音切 30 秒块 |
| 音频加载报错 | 格式/编码问题 | ffmpeg 统一转 16kHz 单声道 wav |
| 噪声环境下识别崩 | 信噪比太低 | 先降噪；检查麦克风采集质量 |
| 同一段音频两次结果不同 | 温度/采样随机性 | `temperature=0` 走贪心解码 |

## 面试常问

**Q：语音识别的基本流程是什么？**
传统路线：音频 → 预处理（采样率统一、分帧）→ 特征提取（MFCC/FBank）→ 声学模型 → 发音词典 → 语言模型 → 文字。端到端路线：音频 → 频谱特征 → 单个神经网络 → 直接输出文字。现代系统（Whisper 等）都是端到端。

**Q：为什么 ASR 用 16kHz 采样率？**
人声的有效信息集中在 8kHz 以下，按奈奎斯特定理 16kHz 足以覆盖；更高的采样率对识别帮助有限却成倍增加计算量。电话场景甚至 8kHz 就够。

**Q：CTC 解决了什么问题？**
语音帧和输出文字之间没有对齐关系（一个字对应多少帧不固定），CTC 通过引入"空白"符号和对所有可能对齐路径求和，让模型可以在没有逐帧标注的情况下训练。

**Q：怎么提升特定领域（如医疗、法律）的识别准确率？**
成本从低到高：initial_prompt 注入术语 → 后处理纠错（术语表替换）→ 用领域数据微调模型。先试最便宜的手段。

**Q：实时语音识别（边说边出字）和离线识别有什么区别？**
实时要求流式模型（如 RNN-T），每收到一小段音频就立刻输出，延迟优先；离线可以整段音频看完再识别，用双向注意力看全局上下文，准确率优先。架构选择上流式模型通常不能用完整的双向编码器。
