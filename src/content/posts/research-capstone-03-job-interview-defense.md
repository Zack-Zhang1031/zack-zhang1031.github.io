## 简历：项目描述的三层写法

简历上的项目描述是淘汰率最高的部分——大多数人写成"负责了什么"，正确的写法是"做成了什么，用什么方法，数字是多少"。以案例平台为例，三层版本：

**一句话版（简历摘要区）：**

> 独立设计并实现 AI 科研内容智能管理与分析平台：采集 48.7 万篇论文元数据，构建语义检索（Recall@10 0.83）、领域自动分类（宏 F1 0.85+）与趋势分析系统，FastAPI + PostgreSQL/pgvector 服务化，Prefect 每日自动化增量，Docker 一键部署。

**bullet 版（项目经历区）**——每条按"动作 + 方法 + 数字"：

- 设计多源采集层（arXiv/OpenAlex/Crossref API + Scrapy/Playwright），实现断点续传与实体对齐，数据质量门零主键重复；
- 构建科研文本分类体系：TF-IDF 基线（宏 F1 0.812 ± 0.006）→ Embedding 路线对比 → 选型决策报告，线上采用 Embedding+LR 方案；
- 实现语义检索与多模态融合，消融实验驱动"标题+摘要+图注"的最优检索单元，Recall@10 提升 4 个点；
- 工程化交付：pgvector 混合查询 P95 <800ms、Prefect 幂等增量管线（含失败告警与日报）、GitHub Actions CI + Docker 容器化部署。

注意每条都有数字，且每个数字都能被追问——它们全部来自[上一课的指标总表](/posts/research-capstone-02-project-retro-portfolio/)，这就是"单一出处"纪律的回报。

**禁区**：别写"熟悉/精通 xx 技术栈"作为项目内容；别写没有数字的过程描述（"负责模型训练和优化"等于什么都没说）；数字不许编——简历上的每个数字都要能在面试里展开成十句话。

## 面试话术：按追问深度准备三层回答

面试官对项目的追问有固定的深度层次，每一层都要准备好：

**第一层：这是什么（30 秒电梯陈述）。** 复用复盘的"问题与约束"段，背到肌肉记忆。检验标准：不看过往文档能一次说清"解决了什么问题、规模多大、你独立做了哪些"。

**第二层：怎么做的（架构与决策）。** 白板画架构图 + 讲 2-3 个决策。话术模板统一用决策记录的三段式："当时有 A/B 两个选项，我选了 A，因为……事后用……验证了"。直接可用的弹药：

- 为什么 Embedding+LR 而不是微调大模型（成本-收益账本）；
- 为什么实体对齐要强弱两档（科研数据宁缺毋滥的精确率优先原则）；
- 为什么近似索引过滤会召回不足以及怎么解（pgvector 的实际运维经验）。

**第三层：遇到过什么困难（失败与权衡）。** 这一层筛掉背项目的人。准备好的真实素材：EDA 时发现某年数据断崖、回溯定位到采集管道字段变更的经历；融合实验里"全文反而拉低指标"的反直觉发现；扫描版 PDF 支线评估后放弃的 ROI 判断。**困难的含金量在于你的排查和决策过程，不在于困难本身**。

## 演示策略：现场打开应用的时刻

有[系列六第 1 课的 Streamlit 应用](/posts/research-capstone-01-streamlit-app/)在，面试可以主动提议演示："这个项目有可以交互的演示，方便的话我可以现场打开。"三分钟的演示动线预先排练：

1. 总览页（10 秒）："48.7 万篇论文，先看规模。"
2. 语义检索页（90 秒）：输入一个**和面试官所在领域相关**的查询（面试前研究对方团队方向，这一步是演示效果的胜负手）。
3. 分类页（40 秒）：贴一篇摘要现场分类，指出置信度条——"低于 0.6 会建议人工确认，这是评估课定的服务水平"。
4. 主题地图（20 秒）："这是无监督发现的主题结构，悬停可以看论文。"

演示的备份方案：现场网络挂掉时，掏出预录的 3 分钟录屏。**演示失败不打紧，没有备份才打紧**。

## 作品集链路：让面试官自助验证

最强的作品集是"面试官不需要问你，自己就能验证"。把链路配齐：

- **GitHub 仓库**：README 即复盘第二段（架构 + 决策），CI 徽章常绿，`m1` 到 `m5` 五个 tag 标记里程碑演进。
- **可交互应用**：Streamlit 演示地址（或录屏视频链接）。
- **博客文章**：本课程的系列文章本身就是深度的最佳证明——面试官读任何一篇都能验证你的理解层次。
- **指标总表**：简历、README、面试话术的数字全部同源。

链路上每一环都指向其他环：简历附仓库链接，仓库 README 附演示链接，演示页脚标注数据与模型版本。面试官从任何一个入口进来，都能走完全部证据。

## 收官：课程的最后一次验收

系列六验收清单（也是整个 27 课课程的毕业标准）：

1. 简历项目描述三层版本完成，每个数字可溯源。
2. 三层面试话术排练过，至少做一次模拟面试。
3. 演示动线排练 + 录屏备份就绪。
4. 作品集链路四环互通，从简历出发 3 次点击内能看到代码、演示和文章。
5. 全部五个里程碑 tag 存在且可检出运行。

## 练习

1. 写出你简历的三层项目描述，逐条标注数字出处。
2. 找同伴做一次 20 分钟模拟面试，记录被问住的三个问题并补进映射表。
3. 录制 3 分钟演示视频，自己看一遍找出节奏问题。
4. 检查作品集链路：从简历链接出发，验证每个环节可达。

## 面试常问（元问题）

**Q：这个项目和学习课程的关系，怎么跟面试官说？**
诚实说：项目是系统学习的载体，但每个决策都经过真实权衡、每个数字都来自真实运行。学习出身不丢人——丢人的是假装它是一线上线系统。它的证明力在于决策密度，不在于流量规模。

**Q：一个人做完整个栈，深度够吗？**
广度的另一面是"知道每个环节的真实成本"。讲清楚在哪些环节做了深入权衡（融合策略、模型选型、索引参数），哪些环节选择了成熟方案及为什么（GROBID、pgvector）——全栈的判断力本身就是深度。

**Q：如果只能展示一件事，展示什么？**
决策记录。代码可以抄、数字可以编，但"当时有什么选项、为什么这样选、事后怎么验证"的思考链很难伪造，也是高级工程师和调参员的分界线。

**Q：课程结束后这个项目还怎么长？**
沿局限清单演进：引用网络的图分析、多标签分类、RAG 问答层（接 [MindTrip 系列](/posts/mindtrip-rag-data-and-retrieval/)的成熟经验）。项目活着，作品集就活着。
