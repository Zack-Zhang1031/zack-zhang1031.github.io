我做分析师时的第一次汇报是场灾难：15 页 PPT 塞了 30 张图，老板翻完问「所以结论是什么？」。后来 mentor 教了我一句话，受用至今：**图表不是数据的展示，是观点的证据。先有观点，再选图**。

这篇分两半：技术层（图怎么选、怎么画、怎么避坑）和叙事层（怎么把图组织成让人听进去的故事）。代码用 matplotlib + plotly，前者出版级静态图，后者交互探索。

**前置阅读**：建议先读 [Pandas 数据分析与可视化](/posts/pandas-data-analysis-visualization/)（数据处理部分）。

## 图表选型决策树

90% 的错误可视化源于选错图型。按「你想表达什么」选：

| 表达意图 | 首选图型 | 反面教材 |
|----------|----------|----------|
| 比较大小 | 条形图（类别多横向） | 饼图（超过 5 块就是灾难） |
| 趋势变化 | 折线图 | 柱状图画 365 天日数据 |
| 占比构成 | 堆叠条形 / 饼图（≤5 块） | 3D 饼图 |
| 分布形态 | 直方图 / 箱线图 | 平均值柱状图（丢分布信息） |
| 两变量关系 | 散点图 | 双 Y 轴折线（伪相关重灾区） |
| 多维下钻 | 热力图 / 分面小图 | 一张图塞 6 种颜色 12 条线 |

两条铁律：**条形图必须从 0 开始**（截断 Y 轴放大差异是经典误导）；**时间序列别用柱状图硬扛**（30 个点以内勉强，以上一律折线）。

## matplotlib：出版级静态图的工程化

```python
import matplotlib.pyplot as plt
import matplotlib.ticker as mtick

plt.rcParams.update({
    "font.family": ["Microsoft YaHei", "PingFang SC", "sans-serif"],  # 中文
    "axes.unicode_minus": False,      # 负号不乱码
    "figure.dpi": 150,
    "axes.spines.top": False,         # 去上右边框——专业感的来源
    "axes.spines.right": False,
})

fig, ax = plt.subplots(figsize=(8, 4.5))
ax.plot(months, revenue, marker="o", color="#1f77b4", label="2026")
ax.plot(months, revenue_prev, color="#999999", linestyle="--", label="2025")

# 强调当前数据点，其余淡化——视觉焦点管理
ax.annotate("8月创新高 ¥2.1M", xy=(7, 2.1), xytext=(5, 2.3),
            arrowprops=dict(arrowstyle="->", color="#d62728"),
            color="#d62728", fontsize=11, fontweight="bold")
ax.set_title("月度营收：连续 6 个月同比增长", loc="left", fontsize=13, fontweight="bold")
ax.yaxis.set_major_formatter(mtick.FormatStrFormatter("%.1fM"))
ax.legend(frameon=False)
fig.tight_layout()
fig.savefig("revenue.png", bbox_inches="tight")
```

三个让图「看起来专业」的细节：**标题写结论不写描述**（「月度营收」→「连续 6 个月同比增长」）；**辅助色用灰**（对比系列淡灰色，焦点系列彩色）；**去掉一切不传递信息的元素**（上右边框、网格默认关、图例边框）。

## plotly：需要交互时的选择

汇报用静态图，**探索用交互图**——异常排查时悬浮看数值、缩放区间、点击图例开关系列，效率差十倍：

```python
import plotly.express as px

fig = px.scatter(df, x="training_hours", y="auc",
                 color="model_type", size="data_size",
                 hover_data=["experiment_id"],   # 悬浮显示实验 ID
                 trendline="ols",                 # 顺手加个回归线
                 title="训练时长 vs AUC：散点与趋势")
fig.write_html("explore.html")   # 保存为可分享的交互页面
```

实验管理场景我常用它画超参探索散点：点大小=数据量、颜色=模型族、悬浮显示实验编号——比翻表格快太多。Dash/Streamlit 可以把这种图包成交互看板，那是后话。

## 五大可视化陷阱（真实事故集）

**1. 截断 Y 轴**。柱状图从 90 起步，95 和 92 看起来差三倍，实际差 3%。除非全组人有共识且标注清楚，否则柱图 Y 轴从 0 起。折线图可以截断，但要接受斜率被放大的代价。

**2. 饼图超过五块**。人眼判断角度和面积的能力极差，7 块饼图里第 3 和第 4 大根本分不清。类别多 → 横向条形图，排序后大小一目了然。

**3. 双 Y 轴阴谋**。两条折线两个 Y 轴，相关性全靠「看起来」——调整左右轴范围可以制造任何你想要的「相关」。要么画散点算相关系数，要么归一化后同轴。

**4. 平均值掩盖分布**。「平均收入 8 万」可能是一人 800 万九人 0。报告关键指标时带上中位数、分位数或直接用箱线图。模型评估同理：平均 AUC 0.9 可能在某个分群上只有 0.6（[A/B 测试那篇](/posts/ab-testing-statistics/)的分层思想）。

**5. 彩虹配色**。jet/rainbow 色阶人眼感知不均匀（黄色区域显得「跳」），连续数据用 viridis，发散数据用 RdBu。分类超过 7 类不要靠颜色区分，分面（facet）成多个小图。

## 数据叙事：金字塔原理的实战版

技术到位后，更大的差距在叙事。老板/客户的大脑和你的不一样——**他们没有上下文，只有 30 秒耐心**。我现在的分析报告结构：

```
结论（1 页）：直接给答案和建议
  └── 支撑论点 A/B/C（各 1 页）
        └── 每页 = 一个论点 + 一张图 + 三行字
              └── 附录：方法、口径、更多图
```

每页图的自查清单：标题是完整句子（论点）吗？图上有没有直接标注关键数字（不让读者自己读轴）？颜色是否只有一个焦点？看完 3 秒能 get 到论点吗？

**前后对比的叙事力**：单看「响应时间 280ms」无感，「优化前 1.2s → 优化后 280ms」立刻有冲击力。没有对比的数字不成观点——和基线比、和目标比、和同期比，总得占一个。

## 一个完整案例：实验效果汇报

需求：向业务方汇报新推荐模型实验结果。差的做法：贴 10 个指标的表格。好的做法：

```
第 1 页：建议全量上线（预期年增收 300 万）
第 2 页：CTR 提升 8.3%（图：两组的对比条形 + 置信区间误差线）
第 3 页：收入指标同步正向，护栏指标无恶化（图：三个指标并排小图）
第 4 页：分人群看，新客提升最显著（图：分组条形，新客高亮）
第 5 页：风险与下一步（灰度计划、长期 holdout 安排）
```

三张图讲完一个故事，每张图只服务一个论点。这种「克制」是练出来的——删掉那些「画都画了」的图。

## 踩坑排查

| 现象 | 原因 | 解法 |
|------|------|------|
| 中文显示为方框 | 字体未配置 | rcParams 设置中文字体族 |
| 负号变方块 | unicode_minus 默认用特殊字符 | axes.unicode_minus=False |
| 保存的图被裁边 | 边界计算不含注解 | savefig 加 bbox_inches="tight" |
| 图在 PPT 里模糊 | dpi 太低或尺寸太小 | figure.dpi≥150，figsize 按最终展示尺寸 |
| plotly 图加载慢 | 数据点几十万全渲染 | 采样或聚合后绘图；大数据用 datashader |
| 同事复现不出图 | 绘图代码和数据耦合在 notebook 里 | 绘图函数化，数据版本化 |

## 练习

1. 找一张「糟糕图表」（百度图片搜「3D 饼图」一堆），列出它违反的每条原则，用 matplotlib 重画一版。
2. 把同一份数据分别画成「描述性标题」和「结论性标题」两个版本，请同事只看 3 秒，对比他们能复述出的信息。
3. 用 plotly 做一张实验探索散点图：至少利用颜色、大小、悬浮信息三个编码通道，保存 HTML 发给同事。
4. 拿一份你最近做的分析，用金字塔结构重排：把结论页放最前面，砍掉一半图，对比两个版本的阅读时长。

## 面试常问

**Q：怎么向非技术高管解释模型评估结果？**
翻译三层：技术指标 → 业务影响 → 决策建议。「AUC 0.94」翻译成「100 个欺诈能抓住 85 个，误拦 1000 个正常交易中的 3 个」再翻译成「建议上线，预计每月止损 50 万，客服投诉增加约 10 单」。永远以建议收尾，不以指标收尾。

**Q：交互式看板什么时候值得做？**
三问：这个问题会被反复问吗（一次性分析别做看板）？数据会定期更新吗？看的人超过 3 个吗？三个「是」才值得投入。否则 notebook 截图发群就是最优解。看板的维护成本（数据管道、权限、口径变更）远超开发成本。

**Q：数据故事和造假的边界在哪？**
选择呈现什么（合理）vs 歪曲呈现方式（违规）。可以：选择最有信息量的对比维度、强调重要发现。不可以：截断轴夸大差异、隐藏不利分组、把相关说成因果。检验标准：把完整数据和方法给一个中立的同行，他能得出兼容的结论。

**Q：matplotlib 和 seaborn、plotly 怎么选？**
matplotlib：底层全能，出版级静态图，定制无上限但代码啰嗦；seaborn：统计图表高层封装（分布、回归、分类图），一行出美图，适合探索分析；plotly：交互和 Web 分享。我的日常：探索用 seaborn/plotly，交付用 matplotlib 精修。
