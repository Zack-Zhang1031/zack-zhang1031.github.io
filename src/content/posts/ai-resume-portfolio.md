筛 AI 工程师简历时，我平均每份花 15 秒。通过的和没通过的差别几乎不在「技术栈列表」，而在**项目描述里有没有「技术决策的痕迹」**。「负责模型训练，准确率 95%」是无效信息；「发现特征穿越导致离线虚高，重建特征管道后线上 AUC 从 0.71 提升至 0.83」——这是会让人停下来的人。

这篇把简历和作品集当作一个「工程项目」来做：目标明确（拿面试）、有验收标准（15 秒测试）、可迭代（按 JD 对齐）。

**前置阅读**：建议先读 [ML 系统设计面试](/posts/ml-system-design-interview/)、[AI 面试与答辩](/posts/research-capstone-03-job-interview-defense/)。

## 项目描述：从「做了什么」到「怎么想的」

**反面教材**（80% 的简历长这样）：

> 基于深度学习的目标检测系统
> - 使用 YOLOv8 训练目标检测模型
> - 准确率达到 95%
> - 负责数据标注和模型部署

问题：任何一个上过课的人都能写——没有信息量。招聘方看到的是「跟过教程」。

**正面写法**（同一项目的重生版）：

> 工业零件缺陷检测系统（实习，独立负责算法侧）
> - 挑战：缺陷样本仅 50 张，良品率 99.9%，直接训练分类器召回不足 40%
> - 决策：采用「异常检测 + 监督检测」双轨方案——PatchCore 用 3000 张良品建正常特征库兜底未知缺陷，YOLOv8 负责已知缺陷分类
> - 结果：漏检率 0.3%，过杀率 4.2%（产线可接受），单件推理 38ms 满足 500ms 节拍
> - 深度：设计「漏检-过杀」权衡曲线与业务方对齐阈值；建立误判回流机制，月度增量训练

公式：**挑战（为什么难）→ 决策（你怎么选的，排除了什么）→ 结果（量化，带约束条件）→ 深度（一个显示思考的细节）**。每条项目 3~5 个 bullet，每个 bullet 都可以被追问三层——而你都答得上，因为是你真做的。

## 量化：没有数字的成就是形容词

量化不是编数字，是**呈现约束与权衡**：

| 弱 | 强 |
|----|----|
| 提升了检索效果 | 召回率从 62% 提升至 89%（自建 100 题评估集） |
| 优化了推理速度 | P99 延迟 800ms → 180ms（量化 + 连续批处理） |
| 降低了成本 | 单请求成本降 67%（缓存命中 40% + 模型降级路由） |

注意括号里的部分——**方法的痕迹**：评估集怎么来的、优化手段是什么。这让数字可信，也给面试官递了追问的钩子（你准备好的战场）。

## GitHub 作品集：15 秒测试的下半场

简历过了初筛，面试官会点进 GitHub。他的 15 秒看三样：

1. **README 是否讲人话**：首屏要有——项目解决什么问题、效果截图/demo 链接、三步跑起来的命令。放一张架构图比三段文字有效。
2. **代码是否像生产代码**：有结构（src/ 分层而非一个 2000 行 notebook）、有配置（config 而非硬编码）、README 里承认局限（「已知问题：长文本检索退化」——承认局限比假装完美更显成熟）。
3. **提交历史**：一周突击 50 个 commit 的「包装仓库」一眼假——持续三个月的迭代历史反而真实。

清理原则：**3 个精品仓库 > 15 个 fork 和烂尾**。每个精品仓库对应简历上的一个项目，互相印证。

## 技术博客：被低估的杠杆

写博客是「一对多」的能力证明：面试官搜你名字，看到你对 RAG 的调优有完整方法论——面试还没开始，信任已经建立。你正在读的这个博客系列（课程笔记 150+ 篇）就是活例子：**学习笔记系统化后，本身就是最强作品集**。

起步建议：复现笔记（[论文复现方法论](/posts/paper-reproduction-method/)的产物）、踩坑记录（真实排错过程比成功故事更受欢迎）、对比评测（A vs B 的实测数据）。每篇博客都是一次「可检索的面试」。

## 对齐 JD：一份简历打天下是懒惰

投前花 10 分钟：JD 里的关键词（RAG/检测/时序/MLOps）在你的简历里能搜到吗？**把最匹配的项目放第一位，技能区按 JD 关键词重排**——ATS 系统和 HR 都是关键词匹配的。但注意：只放你真懂的，JD 对齐不等于吹牛对齐——面试官一问「你 LoRA 的 rank 怎么选的」，答不上来比没写更糟。

## 踩坑排查

| 现象 | 原因 | 解法 |
|------|------|------|
| 简历通过率低 | 项目描述无决策痕迹 | 按「挑战-决策-结果」重写 bullet |
| 面试追问答不上 | 写了没亲手做的部分 | 只写真做的，深度 > 广度 |
| GitHub 被翻后没下文 | README 差/代码乱 | 精品化 3 个仓库，写好 README |
| 数字被质疑 | 无量化口径（「准确率95%」什么集？） | 数字带评估口径和约束 |
| 简历两页还塞不下 | 舍不得删 | 删到一页：只留能赢的项目 |

## 练习

1. 用「挑战-决策-结果-深度」公式重写你最强项目的 4 个 bullet，找同学做 15 秒测试。
2. 给最强的项目仓库写/改 README：首屏放问题定义 + 效果图 + quickstart。
3. 找 3 个目标岗位的 JD，提取关键词清单，检查简历的命中率并调整项目排序。
4. 把一个项目的关键决策写成 800 字博客（为什么选 A 方案不选 B）——这就是面试时的标准答案。

## 面试常问

**Q：简历上最减分的是什么？**
「精通」全家桶（精通 Python/C++/Java/深度学习/大模型——没有重点就是没有深度）、无信息项目（「参与了 xx 项目」没你的角色）、夸大被戳穿（写了「主导」实际是旁观——诚信问题一票否决）、教程项目包装成工作项目（面试官见过的 Titanic/MNIST 比你多）。

**Q：没有实习/工作项目怎么办？**
三条路：① 课程项目做深——同样的课设，做到「挑战-决策-结果」的深度就是项目（[综合实战](/posts/research-capstone-01-streamlit-app/)）；② 开源贡献——给知名项目提 PR（哪怕是文档/测试），是「协作能力」的硬证明；③ 自建项目解决真问题——给自己/朋友做个真有人用的工具，「有 50 个真实用户」比任何课程项目都有说服力。

**Q：面试官怎么验证简历真实性？**
追问三层：你做了什么（个人贡献 vs 团队）→ 为什么这么做（决策依据、排除的方案）→ 深入细节（这个参数怎么定的/如果重做你改什么）。答不上第二层的是「参与过」，答得上第三层的是「真做过」。这也是准备方法：**给每个项目准备三层问答，特别是「踩过的坑」**——坑是真实性的最好证明。

**Q：技术博客对求职的实际作用？**
三个层面：可检索性（HR/面试官搜你名字有内容）、能力前置证明（深度文章 = 免初试）、谈薪筹码（有公开影响力的人议价空间不同）。频率不重要（月更即可），深度重要——一篇被社区转载的踩坑文胜过十篇笔记搬运。

**Q：简历里课程/证书怎么写？**
应届生可以写核心课程（数据结构、机器学习——只写相关的 3~5 门）；证书权重很低（云厂商/课程证书 = 学习经历的注脚，不是能力证明）；GPA 高就写，不高就略过。工作后这些全部让位给项目——简历的黄金位置永远留给「你做成了什么」。
